PASO 2.3 — Modelo de ramas definitivo
---------------------------------------
  main (producción)
    └── develop (integración / staging)
          ├── feat/*      → nuevas funcionalidades
          ├── fix/*       → correcciones de bugs
          ├── chore/*     → mantenimiento, CI, dependencias
          ├── refactor/*  → refactorizaciones sin cambio funcional
          └── release/*   → preparación de releases

  Flujo normal:  feat/* → PR → develop → PR → main → tag → deploy
  Hotfix:        fix/*  → PR → main (directo, para emergencias)

Convención de nombres:
  feat/daic-white-label-branding
  fix/whatsapp-media-timeout
  chore/sync-upstream-v4.7
  release/DAIC-v1.0.0

REGLA: Nunca se hace push directo a `main` ni a `develop`. Siempre vía PR.

PASO 8.1 — Esquema de versionado (Semantic Versioning)
--------------------------------------------------------
[COMPLETADO — 2026-02-12]
Esquema adoptado: DAIC-vMAJOR.MINOR.PATCH

  MAJOR  → Cambio breaking (incompatible con versión anterior)
  MINOR  → Nueva funcionalidad (compatible hacia atrás)
  PATCH  → Corrección de bug

  Ejemplos:
    DAIC-v0.1.0  → Milestone inicial (fork profesionalizado)
    DAIC-v1.0.0  → Primer release estable de producción
    DAIC-v1.1.0  → Nueva feature (ej: integración con n8n)
    DAIC-v1.1.1  → Bugfix
    DAIC-v2.0.0  → Rediseño mayor o upgrade de Chatwoot con breaking changes

  Decisión clave: La versión en package.json (4.10.1) se mantiene intacta
  para evitar conflictos con upstream. El versionado DAIC es independiente
  y se gestiona exclusivamente via tags Git.

PASO 8.2 — Proceso de release
-------------------------------
[COMPLETADO — 2026-02-12]
Proceso documentado y validado. Referencia:

  # 1. Crear rama de release desde develop
  git checkout develop && git pull origin develop
  git checkout -b release/DAIC-vX.Y.Z

  # 2. Actualizar CHANGELOG.md (mover [Unreleased] → [DAIC-vX.Y.Z] - fecha)
  #    NO tocar package.json version (se mantiene sincronizado con upstream).

  # 3. PR: release/DAIC-vX.Y.Z → main
  #    Título: "release: DAIC vX.Y.Z"
  #    Descripción: changelog con todos los cambios desde el último release.

  # 4. Después del merge a main, crear tag y GitHub Release
  git checkout main && git pull origin main
  git tag -a DAIC-vX.Y.Z -m "DAIC vX.Y.Z — descripción breve"
  git push origin DAIC-vX.Y.Z
  gh release create DAIC-vX.Y.Z --title "DAIC vX.Y.Z" --notes-file - < changelog_excerpt

  # 5. Merge back a develop
  git checkout develop && git merge main && git push origin develop
